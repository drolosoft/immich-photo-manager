# MCP 2026-07-28: what changed and how this server handles it

The MCP spec revision `2026-07-28` removed the `initialize` handshake and
protocol-level sessions: every request now carries its protocol version and
client capabilities in `_meta`, servers expose `server/discover`, and results
carry `resultType`. A client that opens with `initialize` (Claude Desktop,
Cowork, Claude Code as of mid-2026) is a **legacy** client; one that sends
per-request `_meta` is **modern**.

This server is **dual-era**: one process, one endpoint, both eras. Built on
the MCP Python SDK v2 (`mcp>=2,<3`), which serves the legacy handshake and
the stateless revision side by side with nothing to configure. Nothing
changes for users: same tools, same JSON/base64 thumbnail contract, same
`MCP_ALLOWED_HOSTS`, same `--transport`.

## How it is verified

| Layer | Where |
|---|---|
| Wire-level dual-era contract (stdio) | `tests/test_dual_era.py` |
| Skills' critical flows on stdio × HTTP × legacy × 2026-07-28, concurrency, auth errors | `tests/test_e2e_both_eras.py` (+ `tests/fake_immich.py`) |
| Another implementation's client (TypeScript SDK v2) | `scripts/crosscheck-ts-client/` |
| Real Immich, both eras, read-only | `scripts/smoke-both-eras.py` |

## Release gate for a version that bumps the SDK

Before tagging:

1. `pytest -q` green on the CI matrix (3.10, 3.13) and locally.
2. `scripts/smoke-both-eras.py` against a real Immich: `ALL GREEN`.
3. A real legacy client (Claude Code / Desktop) lists the tools and runs
   `get_thumbnails_batch` + `get_asset_image` successfully.
4. `scripts/crosscheck-ts-client/run.mjs`: six `ok` lines.

## What we deliberately did not adopt (yet)

Tasks and MCP Apps extensions, `subscriptions/listen`, and the MRTR
`input_required` pattern: this server has no long-running work, no UI, and
never calls the client (no sampling / elicitation / roots), so the core
protocol is enough. Roots, Sampling, and Logging are deprecated in
2026-07-28 and were never used here.
